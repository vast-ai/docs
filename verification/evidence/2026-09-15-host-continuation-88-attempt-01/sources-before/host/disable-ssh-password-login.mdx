Turn off SSH password login to protect your machine. A machine with it enabled
will not pass verification.

The steps are the same on Ubuntu Server 22.04 and 24.04.

<Warning>
Do not turn off password login until a separate key-only connection succeeds.
Keep your current session open and confirm that you have a recovery route before
changing or restarting SSH.
</Warning>

## 1. Check the current setting

This checks the configuration files and prints the effective settings, then
exits. It does not query the running daemon or test a login. Connection-specific
`Match` rules need an appropriate `-C` connection specification.

```bash
sudo sshd -T | grep passwordauthentication
```

```
passwordauthentication yes
```

If it says `no`, the displayed configuration disables the password
authentication method for that evaluation. Still review applicable `Match`
rules and keyboard-interactive settings, and confirm access after applying
changes. If it says `yes`, continue.

<Note>
A fresh Ubuntu install says `yes`. Ubuntu ships the setting commented out, and
sshd enables password login when the setting is absent.
</Note>

## 2. Add your key and confirm it works

From your own computer. Replace `youruser` with your login name on the machine
and `1.2.3.4` with its IP address, here and in every command below.

```bash
ssh-copy-id youruser@1.2.3.4
```

```
Number of key(s) added: 1
```

Now open a second terminal, leaving the first one connected, and log in using
only your key. This proves the key is what is getting you in.

```bash
ssh -o PreferredAuthentications=publickey youruser@1.2.3.4
```

You should get a shell prompt with no password asked.

<Warning>
If you get `Permission denied (publickey)`, stop: that connection did not
authenticate with a key. Check the account, the server’s configured authorized
keys file, ownership and permissions, and the SSH server logs. For the usual
`~/.ssh/authorized_keys` layout, modes `700` for `~/.ssh` and `600` for the file
are restrictive choices; they do not by themselves prove login will work.
</Warning>

## 3. Turn off password login

<Warning>
Do not run this until step 2 worked. If your key is not accepted yet, this locks
you out.
</Warning>

First save a copy of the config you have now. `cp -n` never overwrites, so it is
safe to run this more than once.

```bash
sudo cp -n /etc/ssh/sshd_config /etc/ssh/sshd_config.orig &&
sudo sh -c 'for f in /etc/ssh/sshd_config.d/*.conf; do [ -f "$f" ] || continue; cp -n "$f" "$f.orig" || exit; done'
```

Now set `PasswordAuthentication no` in the SSH config files that have it,
including the extra files Ubuntu keeps in `/etc/ssh/sshd_config.d/`.

```bash
sudo sh -c '
[ -f /etc/ssh/sshd_config ] || exit 1
for file in /etc/ssh/sshd_config /etc/ssh/sshd_config.d/*.conf; do
  [ -f "$file" ] || continue
  sed -i -E "s/^[[:space:]]*#?[[:space:]]*(PasswordAuthentication)[[:space:]]+.*/\\1 no/I" "$file" || exit
done'
```

Successful editing normally produces no output. Check the command’s exit
status and any error messages before continuing.

This updates matching directives, including commented or indented ones, in
the main configuration and existing `.conf` files in the named directory. It
does not add a missing directive or search other include paths.

### Or edit the config yourself

Open `/etc/ssh/sshd_config` and set:

```
PasswordAuthentication no
```

Check the standard drop-in directory for other settings, and review any
custom `Include` paths or applicable `Match` blocks:

```bash
sudo grep -r -i passwordauthentication /etc/ssh/sshd_config.d/ 2>/dev/null
```

Set the relevant `PasswordAuthentication` directives to `no`. Ubuntu’s
shipped configuration includes this directory at the start, so earlier global
values take precedence over later ones. Custom include placement and applicable
`Match` blocks require separate review.

<Warning>
Removing the `#` is not enough. The value must be `no`. A line reading
`PasswordAuthentication yes` still allows passwords.
</Warning>

## 4. Apply and verify

`sshd -t` checks the config for errors. The `&&` means the restart only runs if
that check passes, so a broken config cannot take SSH down. Editing the config
changes nothing until you restart.

```bash
sudo sshd -t && sudo systemctl restart ssh.service
```

Check that both commands completed successfully. Keep the original session
open while you test a new key-only connection; do not rely on silence or assume
that a restart preserves every session.

Recheck the effective configuration on disk. This command does not by itself
confirm that the running service rejects password logins:

```bash
sudo sshd -T | grep passwordauthentication
```

```
passwordauthentication no
```

Repeat the key-only login from step 2 after applying the changes. Review any
connection-specific settings before closing the original session; the `no`
output alone is not a live authentication test.

If it still says `yes`, most likely no config file had the setting. Add it,
then restart and check again:

```bash
echo "PasswordAuthentication no" | sudo tee -a /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh.service
sudo sshd -T | grep passwordauthentication
```

<Check>
Once the output is `passwordauthentication no`, you are done. If your machine
was flagged for password login, the error clears within about two hours.
</Check>

## If you are locked out

You need access that does not go through SSH. Use the machine's IPMI, iDRAC, iLO,
or other BMC console, or plug a monitor and keyboard into it. Then put back
every copy you saved in step 3, and restart:

```bash
sudo sh -c 'for f in /etc/ssh/sshd_config.orig /etc/ssh/sshd_config.d/*.orig; do [ -e "$f" ] && cp "$f" "${f%.orig}"; done'
sudo sshd -t && sudo systemctl restart ssh.service
```

If you changed drop-in files, restore those backups as well as the main
configuration. Ubuntu’s shipped configuration includes the drop-in directory
at the start, so a remaining earlier setting can override a later main-file value.

Log in with your password, fix your key, and start again at step 2. Password
login has to go back off before the machine will verify.
