# Whole-Host clarification review

PLAN_AND_EXECUTE, 10 September 2026. Baseline: baseline-01.json.
Target: the current dirty working tree for CON-1518 / Host Docs PR185.

## Scope and method

Inventory every current page, claim, procedure and node before applying changes.
Population: 44 primary Host pages, 2,013 claims, 116 procedure records and1,085
nodes. The18CLI and15SDK wrappers remain central-reference support layers.

Review the exact wording and context against the user's clarified evidence rules:

1. Basic product descriptions use applicable official publications, not a paid
   rental merely to establish what the product is.
2. An existing approved policy or agreement establishes its matching rule.
   Seek a responsible owner's confirmation only for a missing or unclear rule.
   A request for acknowledgement is not recorded approval, and does not remove
   a required citation. Do not extend an agreement beyond its actual scope.
3. Advice and instructions need review of their reasoning and relevant technical
   facts. An imperative is not automatically a contractual duty or runtime claim.
4. Declared interface settings use canonical code, API schemas or configuration.
   Runtime claims need actual retained observations within their stated scope.
5. Editorial text and links need editorial/static checks, not product approval.
6. Price, payment, legal and tax promises keep the appropriate governing sources.
7. Docs, review metadata, a graph or another unapproved draft cannot be terminal
   proof of the same claim. Preserve partial source support and explicit limits.

Batch compatible checks, with a disposition for each item and explicit exceptions.
Use independent read-only page/claim-category audits alongside main-thread
procedure accounting. Generated summaries are review decisions, never product
evidence. Any material classification/source correction must retain its exact
predecessor and an independently checkable rationale; no automatic PASS from
acknowledgement wording. Status changes need an applicable retained source/check.

## Execution and safety

Only repository inspection, local static/renderer tests, existing evidence/source
binding and anonymous local browser checks. Do not execute Host documentation
commands, access credentials/accounts, rent, SSH, reboot, change policy, install
dependencies, publish, commit, push or merge. Prior paid authorizations are not
renewed by this request. Restart only this repository's local preview if needed.

## Success criteria

- Reconcile all inventory IDs, including unresolved and stale procedure nodes.
- Give each item a suitable review method and each unresolved item a specific
  next action. Do not call missing evidence an external blocker by itself.
- Apply reviewed corrections in shared reader/generator code and exact records,
  with preserved underlying evidence and links to the actual customer passage.
- Retest both the standalone HTML and localhost4000, current-model integrity,
  source/link guards, plain wording, and no circular/unsupported promotion.
- Update REVIEW-TRACEABILITY and the short handoff. Show current findings, not
  historical mistakes, in the reviewer; keep immutable attempts underneath.
- Separate completed repository review from remaining runtime/operator checks
  and genuine source/owner gaps. No human acceptance is inferred.

Disposition coverage is not product validation coverage. A repository-complete
review can still leave claims UNVALIDATED, citation defects FAIL, concrete
prerequisites BLOCKED, and changed historical procedures STALE.
