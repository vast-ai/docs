# Implementation boundary

The clarification sweep is a review of requirements and next actions. It must
not be implemented as friendly labels hiding contradictory evidence requirements.
Where the exact review finds an overbroad method, correct the current recorded
method/rationale as well as its display, with the exact predecessor retained.

Use an additive, pinned transition following the repository's existing authority
adapter convention. The previous model must still pass its original validation.
Only explicitly reviewed fields may change, and both the generator and reader
must independently check the resulting projection. Do not weaken source gates.

This pass may record bounded editorial classifications and review-method
corrections. It may not introduce a product PASS merely by changing a method,
requesting acknowledgement, or confirming that a link exists. Existing PASSs
retain their exact sources and limits. Potential new source closures must first
be assessed for complete scope; a candidate is not a completed adjudication.

For procedure nodes, correct misleading no-action text only. Preserve recorded
statuses, requirements, parents, spans, prior attempts and source limitations.
Unresolved nodes must name their pending check; stale nodes must be remapped
before results transfer. Parent status never inherits a material-claim PASS.

Audits are independent reader proposals, not final authority. The main agent
checks their coverage and exact exceptions before any current record changes.
