Use this page after your machine is ready to list. Hardware matters, but listing settings decide who can find and rent it.

## Core Rule

Revenue is price multiplied by utilization. A high price with low occupancy can earn less than a moderate price with steady rentals.

Before changing settings, compare similar machines by GPU model, GPU count, verification state, region, reliability, storage, bandwidth, and listing duration.

Renters commonly filter by verification state, rental duration, and disk space. If your listing does not pass those filters, price alone will not make it visible to the renters you want.

## Duration

Longer durations can suit renters who need more time, but they extend the period you need to plan for. The [Vast CLI price-increase guidance](https://github.com/vast-ai/vast-cli/blob/ecf32efa1d8d2f110f7de4118c30698bb7ae2fbd/vastai/cli/commands/price_increase.py#L123-L145) states that an existing rental retains its original price through the current end date.

| Shorter duration | Longer duration |
| --- | --- |
| More flexibility | Better fit for long jobs |
| Shorter current price commitment | Longer current price commitment; see the [Vast CLI price-increase guidance](https://github.com/vast-ai/vast-cli/blob/ecf32efa1d8d2f110f7de4118c30698bb7ae2fbd/vastai/cli/commands/price_increase.py#L123-L145). |
| Less commitment | Stronger availability promise |

Different renters value different commitment windows:

| Renter need | Typical duration | Fit |
| --- | --- | --- |
| Automated inference or burst work | Hours to days | Shorter offers preserve flexibility. |
| Experiments and fine-tuning | Days to weeks | Medium durations can balance commitment and occupancy. |
| Training runs or reserved capacity | Weeks to months | Longer offers can attract higher-value, stability-sensitive renters. |

Only offer durations you can honor. The [Vast CLI guidance](https://github.com/vast-ai/vast-cli/blob/ecf32efa1d8d2f110f7de4118c30698bb7ae2fbd/vastai/cli/commands/machines.py#L247-L251) warns that outages during client jobs can lower reliability. [Hosting Agreement — Hardware as a Service Payments](https://cloud.vast.ai/host/agreement) permits withholding for lost user data, excessive outages, extensive downtime, harm to the Vast brand, or provider breach/non-performance.

Use automatic extension deliberately and plan for the additional rental time. If you raise a resource price, the renter must accept the higher extension rate; the current term retains its original price. See the [Vast CLI listing guidance](https://github.com/vast-ai/vast-cli/blob/ecf32efa1d8d2f110f7de4118c30698bb7ae2fbd/vastai/cli/commands/machines.py#L249-L257) and [Vast CLI price-increase guidance](https://github.com/vast-ai/vast-cli/blob/ecf32efa1d8d2f110f7de4118c30698bb7ae2fbd/vastai/cli/commands/price_increase.py#L123-L145).

## Price

Use comparable listings and [market metrics](/host/market-metrics). Adjust from actual utilization, not from the highest visible price.

| If this happens | Consider |
| --- | --- |
| Machine is healthy but idle | Lowering price or improving listing terms |
| Machine is always rented | Testing a modest price increase |
| Similar machines are cheaper | Matching the market until reliability/history improves |
| Demand spikes | Rechecking price after existing contracts end |

Updated offer prices apply to new rentals. Existing rentals keep their current-term rate; a renter can accept a higher rate for an extension after the current end date. See the [Vast CLI price-increase guidance](https://github.com/vast-ai/vast-cli/blob/ecf32efa1d8d2f110f7de4118c30698bb7ae2fbd/vastai/cli/commands/price_increase.py#L123-L145).

## Interruptible Minimum Bid

The minimum bid is a floor, not your expected on-demand price. Set it near the lowest price you are willing to accept, often close to loaded power cost.

If the floor is too high, GPUs may sit idle. If it is too low, interruptible work may not cover operating cost. Do not set the floor close to the on-demand price just because that is the price you hope to receive.

## Disk And Bandwidth

| Setting | Guidance |
| --- | --- |
| Disk price | Price lower if storage is abundant; price higher if disk is scarce. |
| Bandwidth price | Price lower for fast, unmetered links; price higher if bandwidth is metered or capacity-limited. |

Do not let stopped instances, cached images, or rented volumes consume the disk needed for active rentals.

Use the constraint as the pricing signal:

| Resource state | Watch out for |
| --- | --- |
| Excess disk capacity | Pricing storage too high can make the listing less attractive without protecting a scarce resource. |
| Disk-constrained host | Pricing storage too low can let stopped instances or volumes starve active GPU rentals. |
| Fast unmetered bandwidth | A lower bandwidth price can be a competitive advantage. |
| Metered or shared bandwidth | A low bandwidth price can let one renter saturate the connection or create unexpected cost. |

## Min GPU

`min_gpu` controls the smallest GPU slice renters can choose.

| Smaller `min_gpu` | Larger `min_gpu` |
| --- | --- |
| More renters can use the machine | Better fit for full-node workloads |
| Higher fragmentation risk | Lower fragmentation |
| Can improve occupancy | Can miss small-job demand |

For an 8-GPU machine, a `min_gpu` of `2` creates 2x, 4x, and 8x listing options. A `min_gpu` of `8` creates only a full-node option.

For fleets, mix `min_gpu` values across machines instead of setting every host the same way.

| Machine | Example `min_gpu` | Listing options |
| --- | --- | --- |
| A | `1` | 1x, 2x, 4x, 8x |
| B | `2` | 2x, 4x, 8x |
| C | `4` | 4x, 8x |
| D | `8` | 8x only |

Avoid setting every machine to `1` if it creates fragmentation you cannot fill. Avoid setting every machine to full-node only unless you know there is enough demand for that exact GPU class and configuration.

## Keep The Listing Competitive

Basics that affect revenue:

- Keep drivers current before listing.
- Run self-test after setup and major changes.
- Maintain reliability above the verification gate.
- Avoid unplanned reboots, disconnects, and overheating.
- Highlight datacenter status, facility certifications, or compliance claims only when they are real and approved.
