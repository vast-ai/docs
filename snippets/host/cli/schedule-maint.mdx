Schedule an upcoming maintenance window

<Note>This is a **host** command, used for managing machines you are renting out on Vast.ai. First time? Install the CLI via [CLI hello world](/cli/hello-world), then confirm with `vastai --help`.</Note>

## Usage

```bash
vastai schedule maint id --sdate START_DATE --duration DURATION --maintenance_category MAINTENANCE_CATEGORY
```

<Note>`schedule maintenance` is an alias for `schedule maint` if your CLI build supports both spellings. Prefer `maint`. Requires `machine_write` on scoped API keys — see [Permissions](/api-reference/permissions).</Note>

<Note>The CLI prints the window and asks `Continue? [y/n]` before it sends the request. In scripts or cron, pipe the answer (`echo y | vastai schedule maint …`) or call the [REST endpoint](/api-reference/machines/schedule-maint) directly.</Note>

## Arguments

<ParamField path="id" type="integer" required>
  ID of the machine to schedule maintenance for.
</ParamField>

## Options

<ParamField path="--sdate" type="number" required>
  Maintenance start time as Unix epoch seconds (UTC). Required. Omitting it crashes the CLI. Example: `1677562671`. The CLI sends this value to the API unchanged (REST `sdate` is also epoch seconds).
</ParamField>

<ParamField path="--duration" type="number">
  Maintenance duration in whole hours. If you omit it, the server stores a 1-hour window. The server rounds fractional values **down** (minimum 1 hour), so `2.5` is stored as 2 hours. Round **up** when sizing an SLA maintenance window.
</ParamField>

<ParamField path="--maintenance_category" type="string" required>
  One of `power`, `internet`, `disk`, `gpu`, `software`, `other`. Always pass it: if you omit it, the CLI sends `"not provided"`, which the API rejects with HTTP 400. Use `other` when nothing else fits.
</ParamField>

<Note>
The schedule-maintenance API currently stores `maintenance_reason` as empty, so a reason in the REST body is not shown to renters. Send `sdate`, `duration` (whole hours), and `maintenance_category`. See [Schedule Maintenance](/api-reference/machines/schedule-maint).
</Note>

## Description

The lowest-risk path is to wait until all active contracts have expired or the machine is vacant, then take the machine offline.

The same `schedule maint` command is used for both **planned** and **emergency** downtime — advance notice and duration determine maintenance forgiveness, not the category value. Forgiveness can reduce the service credits you owe. It is not a payment to you.

### Planned SLA maintenance

If SLA is enabled and you need planned downtime during an active rental, schedule at least 24 hours in advance. See [SLA Offers → Scheduled maintenance](/host/sla-offers#scheduled-maintenance).

```bash
# Replace MACHINE_ID; --sdate must be a future UTC epoch (≥24h ahead for planned forgiveness review)
# Linux: date -u -d '2 days 02:00:00' +%s
# macOS: date -u -j -v+2d -v2H -v0M -v0S +%s
vastai schedule maint MACHINE_ID \
  --sdate "$(date -u -d '2 days 02:00:00' +%s)" \
  --duration 2 \
  --maintenance_category software
```

### Emergency or unplanned maintenance

If the machine must go offline without adequate notice, still run `schedule maint` to notify renters — but expect the full service-credit amount that can be owed when SLA is enabled. Use the current UTC epoch for `--sdate` and an integer `--duration` (hours):

```bash
vastai schedule maint MACHINE_ID --sdate "$(date -u +%s)" --duration 1 --maintenance_category power
```

To cancel a scheduled window, use [`vastai cancel maint`](/host/cli/cancel-maint). That cancels **every** window you scheduled on the machine. To reschedule, cancel first, then recreate each window you still want (≥24 hours ahead for planned maintenance-forgiveness review). Across many machines, schedule sequentially at least 3 seconds apart (`sleep 3`; the endpoint's `x-rate-limit` threshold is `2.5`). If you still get HTTP 429, wait longer and retry.

## Examples

```bash
vastai schedule maint <ID> --sdate <unix_epoch_seconds> --duration <hours> --maintenance_category software
```
