## Decisions Made
| Decision | Rationale |
|----------|-----------|
| Treat the audit as an inventory, not a blanket execution script | Many Host commands require root, GPUs, account state, rentals, or production access and must not be run indiscriminately. |
| Separate technical validation from stakeholder/source-owner sign-off | Passing syntax and tests cannot prove private control-plane behavior or policy. |
| Preserve exact source file and line references | Reviewers need to reproduce or challenge each finding quickly. |
| Use the existing graph before raw source traversal | Project instructions require graph-first codebase queries and the graph already exists. |
| Label generated CLI/SDK pages separately from authored Host guidance | Generated pages must be checked through their generator/source pipeline rather than counted as independent authored claims. |
| Treat commands as procedure steps, not executable inventory units | Sequential instructions depend on prerequisites, shared state, checkpoints, branches, and cleanup; isolated command execution can produce misleading evidence. |
| Preserve Baseline B but supersede its execution model | Its source carriers, access classifications, static results, and attempts remain useful history, but command-level statuses cannot establish complete user-procedure behavior. |
| Freeze Procedure Baseline P1 before new live execution | Expected results and sequence must be defined before observing runtime outcomes, with append-only change control afterward. |
| Keep semantic-assessment evidence separate from current functional status | A contextual 1–3 assessment must not manufacture runtime PASS; the complete current projection independently owns PASS/BLOCKED/UNVALIDATED/N/A. |
