You can review the published PR now, but ask the author for a containing commit or complete review checkout before comparing its evidence with these totals. Do not copy just the JSON into an older checkout: the source pages, reviewer server and evidence must match.

1. Get a fresh copy of the published PR

Prerequisites: Git, Node.js 24 with npm (the preview’s tested major version), and access to vast-ai/docs. Git clone and npm installation need internet access. No Vast Host key, rental or paid Host test is needed to run the documentation preview.

In a terminal, choose a parent folder where host-docs-pr185 does not already exist:

git clone https://github.com/vast-ai/docs.git host-docs-pr185
cd host-docs-pr185
git fetch origin pull/185/head
git switch --detach FETCH_HEAD
git rev-parse HEAD
git status --short
node --version
npm ci

This creates a separate detached review checkout and installs the lockfile’s dependencies. It does not change your existing worktree. The printed commit identifies the version you are reviewing; PR head may advance after this report was prepared.

For an exact report-snapshot review, first obtain the author’s matching complete checkout. Then verify its current-package digest:

node -e "const fs=require('node:fs'),c=require('node:crypto'); console.log(c.createHash('sha256').update(fs.readFileSync('verification/current-host-docs-review.json')).digest('hex'))"

Expected input SHA-256: __INPUT_SHA256__. A missing file or different digest means a different package. The reviewer also checks source bindings; the JSON digest alone does not prove the entire checkout matches.

4. Review a sentence, then save the feedback

  1. Open the port 4000 page above. Click Review and set your reviewer name.
  2. Read the customer-facing page. In the V&V section, open the relevant statement and use its page-location / proof controls. Confirm what the evidence actually supports.
  3. Select the exact wording for a selection comment, or use Page note for a page-level issue. State the missing source, wrong claim, required decision or unavailable prerequisite.
  4. Use Save JSON to export your feedback, or open the combined review dashboard ↗. Feedback is also saved locally under the directory passed to --dir.
  5. Share the exported feedback with the author. Saving locally does not post to Jira or GitHub. A reviewer name or comment is not recorded acceptance.
  6. When finished, press Ctrl+C in each terminal. Keep your exported JSON and feedback directory.

If you see only the older 40-page baseline or a stale/missing-package warning, stop treating that UI as current. Ask for the matching update; do not force the evidence to PASS. The current package covers 44 Host pages and 33 reference-support layers.

If the local service does not open
  • No review controls: use port 4000, not 3000.
  • Preview unavailable / proxy error: check Terminal 1 is running and the plain page opens. If Mint chose another port, restart Terminal 2 with its --target set to that actual loopback port.
  • Port 4000 already in use: choose another free review port with --port and use that port in your browser. Do not kill an unrelated process.
  • Dependency / Node error: confirm Node 24 in both terminals and run npm ci in the checkout. Both terminals must use the same directory and files.
  • A colleague cannot open your localhost link: expected — 127.0.0.1 refers to their own computer. Share this HTML, or have them start their own checkout. Do not expose the review service to the public network.
