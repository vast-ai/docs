## Before You Install

Complete [Hardware Prep](/host/hardware-prep), [Storage Setup](/host/storage-setup), and [Network & Ports](/host/network-ports). Your account must be host-enabled and the hosting agreement accepted; see [Host Account and Agreement](/host/account-hosting-agreement).

<span id="install-command" aria-hidden="true" />
## Install Command

Copy the current command from the official [Vast host setup page](https://cloud.vast.ai/host/setup/).

The command includes a temporary installation key for the selected account. Copy a fresh command from Setup when installing a machine; a CLI account API key is a different credential.

For team-owned hosts, switch into the intended team context before opening the setup page or copying the command. See [Host Teams](/host/host-teams#install-in-the-right-context).

## Host Installer Wizard

The Host Installer Wizard is Vast's terminal UI for new host machines.

![Host Installer Wizard terminal review screen](/images/host-installer-wizard-tui.png)

Use the current command from the official setup page as the default install path:

1. Sign in to the host-enabled account.
2. Open the [host setup page](https://cloud.vast.ai/host/setup/).
3. Copy the current installer command.
4. Run it on the host, locally or over SSH.
5. Fix failed checks before continuing.

The wizard checks account access, OS/GPU readiness, storage, network ports, network speed, install progress, and self-test readiness.

<Tip>
For SSH installs, keep the session open or use `tmux`.
</Tip>

If the wizard stops at NVIDIA/CUDA checks, inspect the reported failure and confirm that the driver supports the installed GPUs and required CUDA runtime. Repair the driver if needed, reboot if the driver change requires it, and confirm `nvidia-smi` sees the expected GPUs before rerunning the wizard.

<span id="headless-fallback" aria-hidden="true" />
## Headless Fallback

Use the TUI when possible. If the SSH terminal cannot drive it reliably, use the raw installer only after the host is already prepared:

- `nvidia-smi` shows every GPU.
- `/var/lib/docker` is XFS with project quotas.
- TCP and UDP are forwarded for the direct port range.
- You copied a fresh setup-page machine installation key.

<HostInstallCommand />

Do not reset machine identity unless Vast support tells you to.

<span id="install-failures" aria-hidden="true" />
## Install Failures

Common causes:

- Stale setup command.
- Account not fully host-enabled.
- Interrupted installer download.
- Driver or Docker/cgroup problem.
- Blocked ports or low upload speed.
- Storage quota/filesystem mismatch.

Use the wizard error, installer log, and daemon logs to identify and address the failed check. Confirm the intended host account, refresh the setup page and copy its current command before retrying the wizard.

<span id="identify-4xx" aria-hidden="true" />
### Daemon identify or API 4xx errors

If the installer or daemon logs show an HTTP 4xx while registering or identifying the machine, retain the response and check the following possible causes:

1. **Truncated or mangled setup command.** Use the setup page’s copy button to obtain the complete current command for the intended account. Check for a partial paste or unintended edits before retrying; use the actual response to investigate any remaining authentication error.
2. **Setup command or key rejected.** Refresh the setup page and copy its current installer command before retrying. Do not infer the key lifetime or account-agreement state from an HTTP 403 alone.
3. **Account hosting setup incomplete.** Confirm that you selected the intended host account and completed its hosting agreement flow. See [Host Account and Agreement](/host/account-hosting-agreement#agreement-stuck).
4. **Stale installer.** If you are reusing a downloaded installer, return to the setup page and download its current version before retrying. Retain the failing URL and HTTP response from the log if the fresh installer still fails.

If the log shows a local driver, Docker, or cgroup error rather than an API 4xx, use the general causes above and [Host Diagnostics](/host/common-errors-diagnostics#logs).

## Logs

Check `vast_host_install.log`, the `vastai.service` systemd unit, and the kaalia logs. For log locations and diagnostic bundles, see [Host Diagnostics](/host/common-errors-diagnostics#logs).

## After Install

Confirm the machine appears under your host account, then check:

```bash
systemctl is-active vastai.service vast_metrics.service docker nvidia-persistenced.service
findmnt /var/lib/docker -no SOURCE,FSTYPE,OPTIONS
sudo xfs_quota -x -c "state" /var/lib/docker
sudo cat /var/lib/vastai_kaalia/host_port_range
```

Expected:

- Services report `active`.
- `/var/lib/docker` is XFS with `pquota` or `prjquota`.
- XFS project quota accounting and enforcement are ON.
- Port range matches your firewall/router forwarding.

The installer may start self-test automatically. On a fresh host it can wait about 10 minutes for daemon initialization:

```bash
sudo tail -f /var/lib/vastai_kaalia/self_test.log
```

Then continue with [How to Self-Test](/host/how-to-self-test) and [First 24 Hours](/host/first-24-hours).
