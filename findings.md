## Technical Decisions
| Decision | Rationale |
|----------|-----------|
| Inventory commands, errors, thresholds, and behavior claims | These are the main classes of documentation defects that can materially harm a host. |
| Assign a verification tier to every item | This prevents unsafe commands from being treated as routine local tests. |
| Keep unverified items visible | Lack of access or evidence is a finding, not a reason to silently omit a claim. |
| Report generated CLI/SDK references separately | A generated command signature should be validated against its generator/upstream CLI, not treated as an independently authored statement. |
| Reuse the existing owner-question matrix in the final audit | It prevents a static test pass from being misrepresented as proof of private backend or policy behavior. |
| Generate Markdown, JSON, and CSV from one script | Reviewers get a readable checklist, automation gets structured records, and each occurrence remains traceable by stable ID. |
| Treat placeholder sanitization as part of static parsing | The docs intentionally use angle brackets for reviewer-supplied values; Bash syntax validation should test the command structure, not fail on presentation notation. |
| Keep behavior claims as candidates, not automatically verified facts | Extraction identifies statements that deserve evidence; it does not infer that prose is correct merely because it is present. |
| Compare generated self-test output through a temporary file | It verifies drift without overwriting the reviewed page or changing user-owned source checkouts. |
| Record skipped private-source validation as a blocker | A fork CI skip is not equivalent to source synchronization passing. |
| Require exact source SHA matches before claiming generated-page verification | Descendant, feature-branch, or dirty source checkouts may change thresholds/codes and do not prove the checked-in metadata. |
| Report historical-source match and current-head drift separately | The page is reproducible at its declared SHAs, but that does not establish synchronization with today's CLI master. |
| Classify current self-test-reference drift as metadata-only | The content is current at today's branch heads, but regenerating and committing the source-comment SHA would remove the remaining drift. |
| Validate Vast CLI command names through the modular entry point/registry | It is the packaged executable's source of truth and avoids the legacy root script's import-time network request. |
| Invoke `vastai.cli.main:main` directly for help probes | This matches the `pyproject.toml` console-script target and avoids the `python -m` double-module registration artifact. |
| Expand audit coverage to imported Host snippets | Wrapper-page coverage is not rendered-content coverage; imported examples must carry their own file/line provenance and generated-source label. |
| Keep page counts and rendered dependency counts separate | Reviewers should see that 72 routable pages were checked while 33 imported content files were additionally inspected. |
| Add registry-aware CLI validation in addition to Bash parsing | Shell syntax alone cannot detect a wrong executable, nonexistent command, or stale option. |
| Review every automated finding before calling it a defect | Quoted container arguments and prose-level command families are legitimate constructs that a naive flag/signature scan can misclassify. |
| Lead reviewer handoff with the consolidated summary | Reviewers need the confirmed defects and exact commands first; the large inventories remain linked evidence rather than the entry point. |
