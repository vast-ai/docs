Search for instance types using custom query

<Note>
The CLI can find SLA offers but cannot price them. To see the SLA fee in `dph_total`, search in the console or with REST. The CLI also cannot enable SLA at rent—use the [web console](/guides/instances/choosing/sla-coverage#in-the-web-console) or [API automation](/guides/instances/choosing/sla-coverage#api-automation). Details: [Next step for SLA](#next-step-for-sla).
</Note>

**If you only use the CLI today**

1. Use `search offers` to find offers (SLA filters are optional). The CLI price does not include the SLA fee.
2. To rent with SLA, open console Search, set **Reliability target** in the **left Search filters**, confirm an **SLA fee** line, then **RENT**—or follow [API automation](/guides/instances/choosing/sla-coverage#api-automation). `vastai create instance` cannot set `target_reliability`.

## Usage

```bash
vastai search offers [--help] [--api-key API_KEY] [--raw] <query>
```

## Arguments

<ParamField path="query" type="string" required>
  Query to search for. default: 'external=false rentable=true verified=true', pass -n to ignore default
</ParamField>

## Options

<ParamField path="-t" type="string" default="on-demand">
  Show 'on-demand', 'reserved', or 'bid' (interruptible) pricing. default: on-demand (alias: `--type`)
</ParamField>

<ParamField path="-i" type="string">
  Alias for `--type=bid` (alias: `--interruptible`)
</ParamField>

<ParamField path="-b" type="string">
  Alias for `--type=bid` (alias: `--bid`)
</ParamField>

<ParamField path="-r" type="string">
  Alias for `--type=reserved` (alias: `--reserved`)
</ParamField>

<ParamField path="-d" type="string">
  Alias for `--type=on-demand` (alias: `--on-demand`)
</ParamField>

<ParamField path="-n" type="boolean">
  Disable default query (alias: `--no-default`)
</ParamField>

<ParamField path="--new" type="boolean">
  Experimental search path. Behavior and SLA fields may differ from the default search—not recommended for SLA automation or production. Prefer the default search for SLA filtering and `dph_total` quotes.
</ParamField>

<ParamField path="--limit" type="integer">
  Maximum number of offers to return. Prefer an explicit limit when comparing results. CLI `dph_total` never includes the SLA fee. Combine with `--order` / `-o` as needed.
</ParamField>

<ParamField path="--storage" type="number" default="5.0">
  Amount of storage to use for pricing, in GiB. default=5.0GiB. Console, REST, and CLI use different default disk sizes—see [SLA coverage → API automation](/guides/instances/choosing/sla-coverage#api-automation) before REST rent after a CLI search.
</ParamField>

<ParamField path="-o" type="string" default="score-">
  Comma-separated list of fields to sort on. Postfix the field name with `-` to sort descending (for example, `-o 'num_gpus,total_flops-'`). Default: `score-` (alias: `--order`)
</ParamField>

## Examples

<Warning>
The CLI can find SLA offers but cannot price them. Treat `dph_total` as SLA-inclusive only when the search set `target_reliability` in the console or REST. From the CLI, `--order dph_total` sorts by price without the SLA fee. Match `--storage` to `--disk` if you rent via CLI for non-SLA. To **enable** SLA at rent, see [Next step for SLA](#next-step-for-sla) and [SLA coverage](/guides/instances/choosing/sla-coverage#finding-sla-offers).
</Warning>

```bash
# Marketplace reliability score (not SLA commitment)
# rented=false (excludes slots you already rent) is already in the CLI default query; shown here explicitly
vastai search offers 'reliability > 0.98 num_gpus=1 gpu_name=RTX_3090 rented=false'

# Find SLA offers. dph_total here excludes the SLA fee (see the Warning below).
# Always set --storage explicitly when comparing dph_total (CLI default 5 GiB ≠ REST 8 GB).
vastai search offers 'has_sla=true expected_reliability>=0.99' --storage 50 --order dph_total
```

<Warning>
The CLI can find SLA offers (`has_sla`, `expected_reliability`) but cannot price them. `vastai search offers 'target_reliability=0.95'` is sent as `{"eq": 0.95}` and fails with HTTP 400 (`target_reliability: Input should be a valid number`). Treat `dph_total` as SLA-inclusive only when the search set `target_reliability` in the console or REST. From the CLI, `--order dph_total` sorts by price without the SLA fee.
</Warning>

<a id="next-step-for-sla"></a>

**Next step for SLA:** Search only quotes SLA pricing. Enable SLA in the web console (**Reliability target** in **Search filters**, then **RENT**) or via REST `PUT /api/v0/asks/{id}/` with `target_reliability`. Do not use `vastai create instance` expecting SLA. See [SLA coverage](/guides/instances/choosing/sla-coverage#finding-sla-offers).

```bash
# datacenter GPUs with minimum compute capability and TFLOPs
vastai search offers 'compute_cap > 610 total_flops > 5 datacenter=True'

# reliable 4-GPU offers in Taiwan or Sweden
vastai search offers 'reliability>0.99 num_gpus=4 geolocation in [TW,SE]'

# reliable RTX 3090 or 4090 NOT in China or Vietnam
vastai search offers 'reliability>0.99 gpu_name in [RTX_4090, RTX_3090] geolocation notin [CN,VN]'

# nvidia driver 535.86.05 or greater with various constraints
vastai search offers 'disk_space>146 duration>24 gpu_ram>10 cuda_vers>=12.1 direct_port_count>=2 driver_version >= 535.86.05'

# reliable 4+ GPU offers, unverified allowed, sort by num_gpus desc
vastai search offers 'reliability > 0.99  num_gpus>=4 verified=False rented=any' -o 'num_gpus-'

# arm64 cpu architecture only
vastai search offers 'cpu_arch=arm64'
```

**Query syntax (advanced)**

```
query      = comparison comparison...
comparison = field op value
field      = <name of a field>
op         = one of: <, <=, ==, !=, >=, >, in, notin
value      = <bool, int, float, string> | 'any' | [value0, value1, ...]
bool       = True | False
```

- Wrap `>` and `<` in quotes on the command line
- For string values (e.g. `gpu_name`), replace spaces with underscores: `RTX_3090` not `RTX 3090`

**SLA query keys:** `has_sla`, `expected_reliability`, `target_reliability`. In `--raw` output, `dph_total` (also a sort field via `--order dph_total`) and `search.slaPremiumPerHour` are the SLA price fields. `dph_total` (alias `dph`) is also accepted as a CLI query filter, but the CLI cannot send `target_reliability`, so that filter compares the price **without** the SLA fee. To filter on the SLA-inclusive price, use the console or `POST /api/v0/bundles/` with `target_reliability`.

| Field | Meaning |
| --- | --- |
| `dph_total` | Total $/hr including SLA charge when you searched with `target_reliability` |
| `search.slaPremiumPerHour` | SLA fee for that quote |
| `expected_reliability` | Host reliability commitment (also a query key; see Available Fields) |

<Note>
SLA query keys (`has_sla`, `expected_reliability`, `target_reliability`) are accepted by search. Search quotes SLA pricing only. Setting `target_reliability` in search does not enable the SLA at rent time; use console **Search filters → Reliability target** then **RENT**, or REST `PUT /api/v0/asks/{id}/` (not `vastai create instance`) as in [SLA](/guides/instances/choosing/sla-coverage). With `--raw`, the SLA fee for that quote is `search.slaPremiumPerHour`.

The same filters on `POST /api/v0/bundles/` use JSON operators. Match this shape from [SLA → API automation](/guides/instances/choosing/sla-coverage#api-automation): `"has_sla": {"eq": true}`, `"expected_reliability": {"gte": 0.99}`, `"target_reliability": 0.95` (a plain number; `{"eq": 0.95}` is rejected with 400). In that example `allocated_storage` is a number, not an operator object. The current CLI prints `Warning: Unrecognized field` for `has_sla`, `target_reliability`, and `expected_reliability`. The warning is harmless: the fields are still sent. To self-check, run `--raw | jq 'all(.[]; .expected_reliability > 0)'` (CLI `--raw` prints a bare array of offers, not an `offers` object).
</Note>
