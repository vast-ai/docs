This page describes how Vast.ai public API errors and rate limits work, along with practical retry guidance.

## Error Responses

Error responses vary slightly by endpoint. The most common error response shape is:

```json
{
  "success": false,
  "error": "invalid_args",
  "msg": "Human-readable description of the problem."
}
```

Some endpoints omit the boolean `success`.
Some omit `error` and return only `msg` or `message`.

## Rate Limits

### How rate limits are applied

Vast.ai applies rate limits **per endpoint** and **per identity**. This is enforced as a minimum interval between requests for a given endpoint and identity. OpenAPI `x-rate-limit.threshold`, and the `threshold=` value in a 429 message, is that interval in seconds.

For a signed-in API key, the limit is per user account. Extra keys on the same account do not raise it. A call that does not resolve to an account is limited by client IP.

Some endpoints also use **method-specific** limits (GET vs POST) and/or **max-calls-per-period** limits for short bursts.

The combined API reference does not always show each operation's `x-rate-limit` block. For SLA workflows, use this pacing:

| Endpoint | Safe pacing |
| --- | --- |
| Search offers (`POST /bundles/`) | about 10 requests per minute |
| Rent (`PUT /asks/{id}/`) | one call every 4.5 seconds; space calls at least 5 seconds apart |
| Show instances (v1) | one call per second |
| Show charges | one call per second |
| Show earnings and the SLA backtester | one call every 2 seconds |
| Schedule maintenance | one call every 2.5 seconds |
| Create or update a listing (`create_asks`) | one call every 5 seconds |

### Rate limit response behavior

When you hit a rate limit, you will receive **HTTP 429**. There are two families:

- **Legacy endpoints** (rent `PUT /api/v0/asks/{id}/`, `GET /api/v1/instances/`): a plain-text body such as `API requests too frequent: endpoint threshold=…`, with no `Retry-After` header.
- **Token-bucket endpoints** (search `POST /api/v0/bundles/`, charges `GET /api/v0/charges/`): JSON `{"error": "HTTPTooManyRequests", "msg": "API requests too frequent", "retry_after": …}` with a short `Retry-After` header. A daily search quota hit uses the same shape with `"error": "search_quota_exceeded"` and a `Retry-After` that can be hours.

Honor `Retry-After` whenever it is present. If it is absent, back off yourself.

### How to reduce rate limit errors

- **Batch requests** where supported, rather than calling many single-item endpoints.
- **Reduce polling**: use longer polling intervals, or cache results client-side.
- **Spread traffic** over time: avoid bursts; use a queue or scheduler.

If you need higher limits for legitimate production usage, contact support with the endpoint(s), your expected call rate, and your account details.
