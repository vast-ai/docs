Every API key has a set of permissions that control which endpoints it can access. This page is the reference for permission categories, how they map to API routes, and how to build scoped keys.

## You are here if…

| If you… | Start here | API key needed? |
| --- | --- | --- |
| Rent with an SLA in the **web console** | [SLA](/guides/instances/choosing/sla-coverage#in-the-web-console) | No |
| List SLA offers in the **Host** console | [SLA Offers](/host/sla-offers#web-console) | No |
| Automate search, rent, or a host listing | [Client SLA recipe](#client-sla-scoped-key-recipe) or [Host SLA recipe](#host-sla-scoped-key-recipe) on this page | Yes |

On this page, **client** means renter and **provider** means host. Console users do not need **Endpoint Reference by Category** unless they are scoping a key for automation.

For an overview of API key creation and usage, see [Authentication](/api-reference/authentication).

## Permission Categories

Permissions are organized into categories. When you create a scoped API key, you include only the categories the key needs. The available categories are:

| Category | Controls |
|----------|----------|
| `instance_read` | Viewing instances, logs, SSH keys, volumes, deposits |
| `instance_write` | Creating, managing, and destroying instances and volumes |
| `user_read` | Viewing account info, API keys, SSH keys, environment variables, templates |
| `user_write` | Creating/modifying API keys, SSH keys, environment variables, templates, teams |
| `billing_read` | Viewing invoices and earnings |
| `billing_write` | Transferring credit |
| `machine_read` | Viewing machines and reports (hosts) |
| `machine_write` | Managing machines, maintenance, listing/unlisting (hosts) |
| `misc` | Search offers, benchmarks, network volumes, serverless endpoints |
| `team_read` | Viewing team members and roles |
| `team_write` | Inviting/removing team members, managing roles |

## Creating Scoped Keys

<Note>
Renting or listing with an SLA in the web console does not require a scoped API key. Renters start at [SLA](/guides/instances/choosing/sla-coverage#in-the-web-console). Hosts start at [SLA Offers](/host/sla-offers#web-console).
</Note>

Define permissions as a JSON object and pass it when creating a key. The top-level key is always `"api"`, containing the categories you want to grant.

**Example, Instance management with billing access:**

```json
{
  "api": {
    "misc": {},
    "user_read": {},
    "instance_read": {},
    "instance_write": {},
    "billing_read": {},
    "billing_write": {}
  }
}
```

**Example, Instance management without billing:**

```json
{
  "api": {
    "misc": {},
    "user_read": {},
    "instance_read": {},
    "instance_write": {}
  }
}
```

You can create scoped keys using:
- **API**: [Create API Key](/api-reference/accounts/create-api-key)
- **CLI**: [`vastai create api-key`](/cli/reference/create-api-key)
- **SDK**: [`vast.create_api_key()`](/sdk/python/reference/create-api-key)

### SLA workflows (scoped keys)

**Console-only users** do not need a scoped API key to rent or list with an SLA. These recipes are for REST and CLI automation.

| Role | Recipe |
| --- | --- |
| Renter automating search, rent, and verify | [Client SLA recipe](#client-sla-scoped-key-recipe) |
| Host automating list, backtest, and earnings | [Host SLA recipe](#host-sla-scoped-key-recipe) |

**Renters (clients):** Open the [client SLA recipe](#client-sla-scoped-key-recipe) for the JSON and task table. Use `misc` for search, `instance_write` for rent, and `instance_read` for verification. Do not copy the host recipe. You do not need a scoped API key to rent with an SLA in the web console.

**Hosts (providers):** Use every category in the [host SLA recipe](#host-sla-scoped-key-recipe) (the full task table is under `machine_write`). `machine_write` by itself is not enough. Add `misc` if you verify the listing with search offers. Start with [SLA in plain language](/host/sla-offers#sla-in-plain-language). Do not copy the client recipe. Skip that JSON if you only use **Set Pricing → SLA** in the console.

On this page, **client** means renter and **provider** means host.

## Custom Roles

Custom roles let you assign the same set of permissions to multiple team members.

- **Creating roles**: Use the CLI or the Manage page in the web console (requires `team_write` access).
- **Defining permissions**: Select from any combination of the categories listed above.
- **Assigning roles**: Assign created roles to team members through the team management interface or CLI.

## Constraints

Constraints narrow a permission category to specific parameter values. This lets you create keys that can only operate on certain resources.

**Example, Read logs for a single instance only:**

```json
{
  "api": {
    "instance_read": {
      "api.instance.request_logs": {
        "constraints": {
          "id": {
            "eq": 1227
          }
        }
      }
    }
  }
}
```

**Example, Read logs for a range of instance IDs:**

```json
{
  "api": {
    "instance_read": {
      "api.instance.request_logs": {
        "constraints": {
          "id": {
            "lte": 2,
            "gte": 1
          }
        }
      }
    }
  }
}
```

Supported constraint operators: `eq`, `lte`, `gte`.

<Note>
API keys using constraints must be created via the CLI ([`vastai create api-key`](/cli/reference/create-api-key)) or the API ([Create API Key](/api-reference/accounts/create-api-key)).
</Note>

You can also use **wildcards** in `params` to represent placeholder values, useful when generating many keys that perform similar operations.

<a id="host-sla-scoped-key-recipe"></a>

**Host only — minimum SLA API key.** Skip this JSON if you only use **Set Pricing → SLA** in the console. Create via [Create API Key](/api-reference/accounts/create-api-key). See [Creating Scoped Keys](#creating-scoped-keys) for the required `api` wrapper. Enable every category in the JSON below. `machine_write` by itself cannot backtest, list, and read earnings. The **`misc`** category is broader than search: it also covers other routes such as serverless groups. You cannot limit `misc` to search only. Use a separate key for SLA scripts.

```json
{
  "api": {
    "machine_read": {},
    "machine_write": {},
    "billing_read": {},
    "misc": {}
  }
}
```

`misc` is required for `vastai search offers` / `POST /api/v0/bundles/`. Omit it if you only check the listing in the console.

| Task | Permission | Console fallback |
| --- | --- | --- |
| List or update an SLA offer (`PUT /api/v0/machines/create_asks/`) | `machine_write` | **Set Pricing → SLA**, then **LIST** |
| SLA backtester | `machine_read` | Console SLA preview |
| Schedule / cancel maintenance | `machine_write` | [Set a maintenance window](/host/set-maintenance-window) (Host → Machines → Settings → Machine Maintenances), or CLI/REST. SLA service-credit rules: [Scheduled maintenance](/host/sla-offers#scheduled-maintenance). |
| Monitor `sla_earn` | `billing_read` | Host → Billing / Earnings |
| Verify the listing in search | `misc` | **Host → Machines** (no API key) |

Earnings URLs look like `/api/v0/users/{user_id}/machine-earnings/`. Copy `{user_id}` from **Account → Profile**. If `vastai show user` is denied on this key, add `user_read`.

<a id="client-sla-scoped-key-recipe"></a>

**Client (renter) only — search and REST rent.** You do not need this JSON to rent in the web console. Create the key via [Create API Key](/api-reference/accounts/create-api-key). Hosts should use the [host SLA recipe](#host-sla-scoped-key-recipe), not this one.

- **Search:** `misc` for `POST /api/v0/bundles/` and CLI `search offers`. There is no search-only permission. `misc` also covers other routes, such as serverless. Use a dedicated key if you do not want SLA automation to include those routes.
- **Rent:** `instance_write` on `PUT /api/v0/asks/{id}/` with `target_reliability`.
- **Verify:** `instance_read` with `GET /api/v1/instances/` or `vastai show instances-v1 --raw`. On a running instance, the SLA fee is `instance.slaPremiumPerHour`. Search-context fields on that same payload use `search.slaPremiumPerHour`.

```json
{
  "api": {
    "misc": {},
    "instance_write": {},
    "instance_read": {}
  }
}
```

This is the minimum for search, REST rent, and verification. Add `user_read` if the flow loads templates or account profile data, and `user_write` if it creates SSH keys or templates. See the instance-management example under [Creating Scoped Keys](#creating-scoped-keys).

| Task | Category | Console fallback |
| --- | --- | --- |
| Search SLA offers | `misc` | **Search** |
| Rent with an SLA | `instance_write` | Console **RENT** |
| Verify `target_reliability` | `instance_read` | **Instances** |

**Service credits:** Use the web console (**Account → Billing**) to view SLA credits. The Charges API (`GET /api/v0/charges/`) does not yet include SLA settlement line items; `items[].type` is limited to `gpu`, `disk`, `bwd`, and `bwu`.

<Note title="API integrators">
OpenAPI documents charge `type` values only; do not use this endpoint alone to reconcile SLA credits.
</Note>
